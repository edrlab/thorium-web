# Migration Guide: 1.8.0

This release introduces **read along**: EPUB and WebPub publications can be read aloud with text-to-speech, with the sentence and word being read highlighted. It is a breaking change for TypeScript integrations that create their own reader preferences or themes, as read along adds required preferences and theme tokens.

---

## Overview of changes

| Area | Change |
|---|---|
| Dependencies | `@readium/navigator` `2.13.0` or later, `@readium/navigator-html-injectables` `2.9.1` or later |
| Settings storage | With a `localDataKey` or `settingsStorage`, most settings are stored **per publication** by default |
| Reader themes | `readAlongUtterance`, `readAlongWord` and `readAlongMask` tokens **required** (`ThReaderThemeTokens`) |
| `ThPreferences` | New **required** `readAlong` property |
| `ThPreferences.actions.keys` | New **required** `readAlong` action tokens |
| Docking | A docker with a single option is no longer shown |
| Playback buttons | `StatefulPlayPauseButton`, `StatefulSkipBackwardButton` and `StatefulSkipForwardButton` **require** `className` |
| Redux store | New `readAlongSettings` and `readAlongPlayer` slices, both persisted |
| Plugins | New `readAlongActions` map, and `"readAlongVoice"`, `"readAlongHighlight"`, `"readAlongProsody"` and `"readAlongVerbosity"` settings types |
| Playback components | Buttons, cover, actions and hooks shared by the audio and read-along players |
| Core components | New `ThCover`, `ThMiniPlayer`, `ThPlaybackControls` and `ThPublicationMetadata` |
| Core hooks | New `useReadAloudNavigator`; `useNavigator()` gains `readAloud` and `playback`; `usePrevious` returns the value before the last change |
| Reader hooks | `useReaderTransitions` flags last until the next reader-state change |
| Sheets | New `headerActions` prop and `useBottomSheetSnap` hook; `ThBottomSheet`’s `isDismissable` also drives focus containment |

---

## Breaking: `@readium/navigator` version

Read along needs a `@readium/navigator` release that includes `ReadAloudNavigator` and its read-along preferences: `2.13.0` or later.

`@readium/navigator-html-injectables`, a peer dependency, goes with it: `2.9.1` or later.

---

## Breaking: read-along tokens required in reader themes

Reader themes are now typed with `ThReaderThemeTokens`, which extends `ThemeTokens` with the colors of the read-along highlight. Every theme in `theming.themes.keys` of your reader preferences must define them. Audio themes are unchanged.

### Before (1.7.x)

```typescript
theming: {
  themes: {
    keys: {
      [ThThemeKeys.light]: lightTheme,
      myTheme: {
        background: "#fefefe",
        text: "#111111",
        // ... other ThemeTokens
      }
    }
  }
}
```

### After (1.8.0)

```typescript
theming: {
  themes: {
    keys: {
      [ThThemeKeys.light]: lightReaderTheme,
      myTheme: {
        background: "#fefefe",
        text: "#111111",
        // ... other ThemeTokens
        readAlongUtterance: "#fff4b3",  // Sentence being read
        readAlongWord: "#ffcf3f",       // Word being read
        readAlongMask: "#fefefe99"      // Dims everything but the sentence, e.g. the background with transparency
      }
    }
  }
}
```

The built-in themes have reader versions including these tokens: `lightReaderTheme`, `darkReaderTheme`, `paperReaderTheme`, `sepiaReaderTheme`, `contrast1ReaderTheme`, `contrast2ReaderTheme` and `contrast3ReaderTheme`. Keep `lightTheme` and `darkTheme` for audio themes.

See [Theming](../customization/Theming.md#keys-and-tokens).

## Breaking: `readAlong` preferences required

`ThPreferences` has a new required `readAlong` property, configuring the read-along players’ actions and settings, and `actions.keys` requires tokens for the new `ThActionsKeys.readAlong` action.

### Before (1.7.x)

```typescript
const prefs = createPreferences({
  actions: {
    reflowOrder: [ThActionsKeys.settings, ThActionsKeys.toc],
    keys: {
      [ThActionsKeys.settings]: defaultSettingsAction,
      [ThActionsKeys.toc]: defaultTocAction
    }
  },
  // ... rest of preferences
});
```

### After (1.8.0)

```typescript
const prefs = createPreferences({
  actions: {
    reflowOrder: [ThActionsKeys.settings, ThActionsKeys.toc, ThActionsKeys.readAlong],
    keys: {
      [ThActionsKeys.settings]: defaultSettingsAction,
      [ThActionsKeys.toc]: defaultTocAction,
      [ThActionsKeys.readAlong]: defaultReadAlongAction
    }
  },
  readAlong: defaultReadAlongPreferences,
  // ... rest of preferences
});
```

The tokens are required even if you don’t add the action to an order. Without the action in an order, read along isn’t offered.

See [Read Along](../customization/ReadAlong.md) to configure it.

## Breaking: a docker with a single option is hidden

A docker used to be hidden only when its single option was undocking. It is now hidden whenever a single option is left, e.g. a [reserved](../customization/Docking.md#reserved-actions) action with one dockable slot, as there is nothing to choose.

## Breaking: playback buttons require `className`

`StatefulPlayPauseButton`, `StatefulSkipBackwardButton` and `StatefulSkipForwardButton` are shared by the audio and read-along players, and no longer render a class of their own. `StatefulAudioPlaybackControls` passes the audio classes, so the audio player is unchanged.

If you render these buttons yourself, pass a `className`. To keep the audio styles, use:

- `StatefulPlayPauseButton`: `thorium_web_audioPlayback_audioPlayPauseButton`
- `StatefulSkipBackwardButton`: `thorium_web_audioPlayback_audioSkipBackwardButton`
- `StatefulSkipForwardButton`: `thorium_web_audioPlayback_audioSkipForwardButton`

They are now exported from the `divina`, `epub`, `webpub` and `reader` packages too, and pick their icons and labels from the reader profile: replay and forward intervals in audio, previous and next sentence in read along.

---

## Breaking: new store slices

`readAlongSettings` (read-along preferences) and `readAlongPlayer` (player state) are added to the default store, and persisted.

If you use the default store, possibly with external reducers, nothing changes. If you pass your own store through the `store` prop, add `readAlongSettingsSlice.reducer` and `readAlongPlayerSlice.reducer` under these keys.

See [Store](../packages/Core/API/Store.md#readalongsettings-reducer).

---

## Breaking: settings stored per publication

With a `localDataKey` or a `settingsStorage` on the reader, most settings are now stored per publication, in IndexedDB, according to `defaultSettingsStorageStrategies`: a publication opened for the first time starts from the last values used, then keeps its own. Without either, every setting stays shared by all publications.

To keep a setting shared by all publications, give it the `global` strategy in your own strategies, passed to `ThStoreProvider`’s `settingsStorageStrategies` or to `makeStore`. To store per-publication settings elsewhere than IndexedDB, pass a `settingsStorage`.

See [Settings Storage Strategies](../packages/Core/API/Store.md#settings-storage-strategies) and [SettingsStorage Interface](../packages/Reader/ReadMe.md#settingsstorage-interface).

---

## Breaking: `usePrevious` returns the value before the last change

`usePrevious` used to return the value from the previous render, so `previous !== value` was true for one render after a change, and effects depending on it ran again on the next unrelated render. It now returns the value before the last change:

- `previous` changes only when `value` changes, and `previous !== value` stays true until the next change.
- It is `null` until `value` first changes, not only on the first render.
- `value` must keep its identity across renders: pass a primitive or a memoized value.

`useReaderTransitions` follows: its `was*`, `from*` and `to*` flags describe the latest change of the reader state and stay set until the next one. If you used `previous !== value` or these flags as a one-render signal, react to the change with an effect depending on the value instead.

See [usePrevious](../packages/Core/API/Hooks.md#useprevious) and [useReaderTransitions](../packages/Reader/Hooks.md#usereadertransitions).

## New: read along

- **Action:** `ThActionsKeys.readAlong` starts read along in a mini player, in the bottom bar or in a bottom sheet. It expands into a player docked at the end by default.
- **Components:** the read-along components are exported from the `divina`, `epub`, `webpub` and `reader` packages. See the [Read Along API Reference](../packages/Epub/API/ReadAlong.md).
- **Preferences:** `readAlong`, `ThReadAlongActionKeys`, `ThReadAlongKeys`, `useReadAlongPreferences`, and the `readAlongAction`, `readAlong`, `readAlongVoice`, `readAlongHighlight`, `readAlongProsody` and `readAlongVerbosity` customizable keys. See [Read Along](../customization/ReadAlong.md).
- **Plugins:** actions of the read-along players go in the new `readAlongActions` map, voice components use `type: "readAlongVoice"`, highlight components use `type: "readAlongHighlight"`, prosody components use `type: "readAlongProsody"`, and verbosity components use `type: "readAlongVerbosity"`.

---

## New: shared playback components

Components used by both the audio and read-along players are shared, following the settings components. They render no class of their own: each player passes its own, so read along only renders `thorium_web_readAlong*` classes and audio keeps its classes unchanged.

- **Controls:** `StatefulPlayPauseButton`, `StatefulSkipBackwardButton`, `StatefulSkipForwardButton` (see [Breaking: playback buttons require `className`](#breaking-playback-buttons-require-classname)) and `StatefulCover`.
- **Actions:** `StatefulVolumeTrigger`/`Container`, `StatefulPlaybackRateTrigger`/`Container`, `StatefulSleepTimerTrigger`/`Container` and `PlaybackActionPair`. The audio actions (`StatefulAudioVolumeTrigger`, etc.) keep their names and render these with the audio classes.
- **Hooks:** `usePlaybackStatus`, `useVolumeAction`, `usePlaybackRateAction`, `useSleepTimerAction` and `useSleepTimerCountdown`. See [Audio Hooks](../packages/Audio/API/Hooks.md#playback-hooks).
- **Read along:** `StatefulReadAlongVolumeTrigger`/`Container`, `StatefulReadAlongRateTrigger`/`Container` and `StatefulReadAlongSleepTimerTrigger`/`Container` are the default components of the `readAlongActions` map, with `thorium_web_readAlongVolume_*`, `thorium_web_readAlongRate_*` and `thorium_web_readAlongSleepTimer_*` classes. See [Read Along API](../packages/Epub/API/ReadAlong.md).

They are exported from the `audio`, `divina`, `epub`, `webpub` and `reader` packages. See [Audio Controls](../packages/Audio/API/Controls.md).

---

## New: core components and hooks

- `ThCover`, `ThMiniPlayer`, `ThPlaybackControls` and `ThPublicationMetadata`: see [Playback Components](../packages/Core/API/Components/Playback.md).
- `useReadAloudNavigator`, and `getInstance` on `useEpubNavigator` and `useWebPubNavigator`: see [Core Hooks](../packages/Core/API/Hooks.md#read-aloud-navigator-hook).
- `useNavigator()` gains `readAloud` (`null` until loaded) and `playback`, which drives playback buttons with the read-aloud navigator or the media navigator: see [Navigator Context](../packages/Core/API/Hooks.md#navigator-context).

---

## Changed: sheets and docking

- `ThBottomSheet`’s `isDismissable` (default `true`) now also controls focus containment. With `false`, the sheet leaves the page usable.
- `StatefulSheet` accepts `headerActions`, extra buttons rendered in the header before the close button.
- `StatefulBottomSheet` moved to `Sheets/BottomSheet/`, with its snapping extracted into `useBottomSheetSnap`. The package exports are unchanged.
- `useDocking` accepts `{ canReserve }`, to reserve a dock slot only while it applies.

## Migration checklist

- [ ] Update `@readium/navigator` to `2.13.0` or later, and `@readium/navigator-html-injectables` to `2.9.1` or later
- [ ] Add `readAlongUtterance`, `readAlongWord` and `readAlongMask` to every custom reader theme, and use the `*ReaderTheme` constants for built-in ones
- [ ] Add `readAlong` to your reader preferences, e.g. `defaultReadAlongPreferences`
- [ ] Add `actions.keys.readAlong`, e.g. `defaultReadAlongAction`, and `ThActionsKeys.readAlong` to the orders where it should be offered
- [ ] If you pass your own store, add `readAlongSettingsSlice.reducer` and `readAlongPlayerSlice.reducer` under `readAlongSettings` and `readAlongPlayer`
- [ ] If you pass a `localDataKey` or `settingsStorage`, check which settings should stay shared by all publications, and give them the `global` strategy
- [ ] Check dockers you expected to show with a single option
- [ ] Pass a `className` to `StatefulPlayPauseButton`, `StatefulSkipBackwardButton` and `StatefulSkipForwardButton` if you render them yourself
- [ ] Check code relying on `usePrevious` or `useReaderTransitions` flags lasting one render
