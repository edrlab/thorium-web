# Migration Guide: 1.8.0

Cover URLs are no longer routed through a hardcoded `/api/proxy` route. Integrations that relied on it must now provide their own resolver.

Integrations whose covers are relative URLs, or served with CORS headers, do not need any change.

---

## Breaking: cover proxy is no longer built in

Up to 1.7.x, absolute http(s) cover URLs were rewritten to `/api/proxy?url=…` before being fetched, whether or not that route existed in the host app. They are now used unchanged unless a resolver is provided.

The audio player fetches covers to display them and to generate its theme, so external covers without CORS headers fail to load without a resolver.

### Before (1.7.x)

```tsx
<StatefulReaderWrapper
  profile={ profile }
  publication={ publication }
  localDataKey={ localDataKey }
/>
```

### After (1.8.0)

```tsx
const resolveCoverUrl = (url: string) => `/my-proxy?url=${ encodeURIComponent(url) }`;

<StatefulReaderWrapper
  profile={ profile }
  publication={ publication }
  localDataKey={ localDataKey }
  resolveCoverUrl={ resolveCoverUrl }
/>
```

When using `StatefulPlayer` without `StatefulReaderWrapper`, provide the resolver with `ThCoverUrlResolverContext` from `@edrlab/thorium-web/audio` instead:

```tsx
import { ThCoverUrlResolverContext } from "@edrlab/thorium-web/audio";

const resolveCoverUrl = (url: string) => `/my-proxy?url=${ encodeURIComponent(url) }`;

<ThCoverUrlResolverContext.Provider value={ resolveCoverUrl }>
  { /* ... */ }
</ThCoverUrlResolverContext.Provider>
```

Only absolute http(s) URLs are passed to the resolver. Relative and `blob:` URLs are used as-is.
