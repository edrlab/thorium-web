# Migration Guide: 1.7.0

This release adds a fourth reader profile, **Divina**, for image-based publications (comics, manga, webtoons). It is a breaking change for any integration that builds a full `ThPreferences` object, since Divina display orders and paginated affordances are now required.

Integrations relying on `defaultPreferences`, or extending them, do not need any change.

---

## Overview of changes

| Area | Change |
|---|---|
| Package | New `@edrlab/thorium-web/divina` and `@edrlab/thorium-web/divina/styles` entry points |
| Peer dependencies | `@readium/navigator` `^2.11.1`, `@readium/shared` `^2.6.0`, `@readium/navigator-html-injectables` `^2.8.4` |
| `ThPreferences` | `actions.divinaOrder`, `settings.divinaOrder`, `settings.keys.divinaQuality`, and `affordances.paginated.divina` **required** |
| `ThPreferences` | New `divina` entries for `theming.layout.ui`, `theming.progression.format`, and `theming.header.runningHead.format` |
| `ThSettingsKeys` | New `divinaQuality`, `divinaSpreads`, and `divinaStripWidth` keys |
| Profile | `"divina"` added to the profile union (`usePublication`, `StatefulReaderWrapper`, store) |
| `ReaderPlugins` | New `divina` factory |
| Redux store | New `divinaSettings` slice, `publication.isManifestScrolled`, and `divina` buckets in `actions` |
| `StatefulLayout` | Moved to the shared settings components – exported from `epub` and `divina` |
| Hooks | New `useDivinaNavigator` |

## Breaking: Divina keys required in `ThPreferences`

`actions.divinaOrder`, `settings.divinaOrder`, and `affordances.paginated.divina` are required, like their `reflow`, `fxl`, and `webPub` counterparts. So is `settings.keys[ThSettingsKeys.divinaQuality]`.

### Before (1.6.x)

```tsx
import { createPreferences } from "@edrlab/thorium-web/core/preferences";

const prefs = createPreferences({
  // ... rest of preferences
  affordances: {
    // ...
    paginated: {
      reflow: { /* ... */ },
      fxl: { /* ... */ }
    }
  },
  actions: {
    reflowOrder: [ /* ... */ ],
    fxlOrder: [ /* ... */ ],
    webPubOrder: [ /* ... */ ],
    // ...
  },
  settings: {
    reflowOrder: [ /* ... */ ],
    fxlOrder: [ /* ... */ ],
    webPubOrder: [ /* ... */ ],
    // ...
  }
});
```

### After (1.7.0)

```tsx
import { DivinaQuality } from "@readium/navigator";
import {
  createPreferences,
  ThActionsKeys,
  ThArrowVariant,
  ThSettingsKeys
} from "@edrlab/thorium-web/core/preferences";

const prefs = createPreferences({
  // ... rest of preferences
  affordances: {
    // ...
    paginated: {
      reflow: { /* ... */ },
      fxl: { /* ... */ },
      divina: {
        default: {
          variant: ThArrowVariant.layered,
          discard: ["navigation"],
          hint: "none"
        }
      }
    }
  },
  actions: {
    reflowOrder: [ /* ... */ ],
    fxlOrder: [ /* ... */ ],
    webPubOrder: [ /* ... */ ],
    divinaOrder: [
      ThActionsKeys.settings,
      ThActionsKeys.toc,
      ThActionsKeys.fullscreen,
      ThActionsKeys.jumpToPosition
    ],
    // ...
  },
  settings: {
    reflowOrder: [ /* ... */ ],
    fxlOrder: [ /* ... */ ],
    webPubOrder: [ /* ... */ ],
    divinaOrder: [
      ThSettingsKeys.theme,
      ThSettingsKeys.layout,
      ThSettingsKeys.divinaSpreads,
      ThSettingsKeys.divinaStripWidth,
      ThSettingsKeys.divinaQuality
    ],
    keys: {
      // ...
      [ThSettingsKeys.divinaQuality]: {
        choices: [DivinaQuality.auto, DivinaQuality.low, DivinaQuality.high, DivinaQuality.max]
      }
    }
    // ...
  }
});
```

The values above are the defaults. If you do not want to support Divina publications, you can set both display orders to empty arrays.

> [!NOTE]
> The `choices` of `settings.keys[ThSettingsKeys.divinaQuality]` restrict the image qualities offered to users, for instance if your platform does not serve `max` variants.

## New: `"divina"` profile

`usePublication` now returns `"divina"` when the manifest’s `conformsTo` contains the Divina profile. It is checked after audio and before EPUB.

```tsx
// profile may now be "epub" | "webPub" | "audio" | "divina" | null
const { profile } = usePublication({ url });
```

`StatefulReaderWrapper` handles it automatically, and accepts the same `preferences` shape as EPUB and WebPub (`ThPreferences`). Divina-specific plugins can be provided through the new `divina` factory:

```tsx
<StatefulReaderWrapper
  profile={ profile }
  publication={ publication }
  localDataKey={ localDataKey }
  plugins={{
    epub: () => [ createDefaultPlugin() ],
    divina: () => [ createDefaultPlugin(), myDivinaPlugin ]
  }}
/>
```

If you mount readers directly, use `StatefulDivinaReader` from `@edrlab/thorium-web/divina`. See the [Divina package](../packages/Divina/ReadMe.md).

> [!IMPORTANT]
> If you branch on `profile` in your own code, make sure `"divina"` is handled. Divina shares the Fixed-Layout theme slot (`state.theming.theme.fxl`) and `theming.themes.fxlOrder`.

## Redux store

- A new `divinaSettings` slice (`quality`, `scrolled`, `spreads`, `stripWidth`) is added and persisted.
- `publication.isManifestScrolled` is `true` when a Divina manifest declares `layout: "scrolled"` (webtoons), set with `setManifestScrolled`.
- `actions.dock` and `actions.keys` gain a `divina` bucket.

Persisted states from previous versions are migrated on load: missing profile docks are created, and `usePublication` dispatches `ensureProfileActions` for the detected profile. No action is required.

If you provide your own store, add `divinaSettingsSlice.reducer` under the `divinaSettings` key.

---

## `StatefulLayout` moved to shared settings

`StatefulLayout` now handles both EPUB (`scroll`) and Divina (`scrolled`) and lives with the shared settings components. Like other shared components, it is exported from every entry point, including `@edrlab/thorium-web/epub` and `@edrlab/thorium-web/divina`, so existing imports do not change.

`StatefulTheme` and `StatefulJumpToPositionContainer` now go through `useNavigator()` instead of `useEpubNavigator()`, so that they work with every visual navigator. This only matters if you copied them to build your own components.
